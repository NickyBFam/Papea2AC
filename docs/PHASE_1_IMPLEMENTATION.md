**2026-09-16 continuation session (semantic normalization pass — closing the remaining 24 gaps):** re-derived the 24 directly from `packet-coverage.tsv`'s `mandatory=true` rows not marked `FULLY NORMALIZED` (22 tagged `MANDATORY GAP` plus `bundle_delimiter` and `explode`, both previously `METADATA-ONLY` with `mandatory=true`) rather than trusting the prior session's list from memory; the re-derivation matched exactly.

*Item and data-component model.* Modern Minecraft items are not NBT/`ItemMeta` — an `ItemStack` carries a `DataComponentMap` keyed by singleton `DataComponentType<?>` instances. `SemanticPayload.Item` models this directly: an `empty` flag, the item's registry key, count, and three explicitly known, individually typed components (`damage`, `maxDamage`, `unbreakable`) plus a typed `enchantments` list (registry key + level, sorted by key so encoding never depends on native map/set iteration order). Every other present component is disclosed only by its registry key in a bounded (64), deduplicated, sorted `otherComponents` list — never silently dropped, never leaked as a native `DataComponentType`/value object, and never guessed at content it cannot type. `ServerboundContainerClickPacket`'s changed-slot and carried-item fields are represented even more conservatively: the native `HashedStack` type (verified via `javap`) exposes only `matches(ItemStack, HashGenerator)`, no accessor for its actual content, so `ContainerClickClaim`/`ChangedSlot` record index and empty/non-empty state only — this is a case where the honest, bounded observation is deliberately less than "the item," because that is genuinely all that reaches the server on the wire in this version.

*Chunk and light representation.* `ChunkBaseline` (backing `level_chunk_with_light`) and `LightUpdate` never explode into per-block or per-light-value objects: they carry chunk coordinates, a bounded encoded byte length for the block/heightmap/light buffers, and block-entity/heightmap/section counts — proportional to one allocation per packet, not per block. `SectionBlocksUpdate`/`BlockUpdate` do represent each changed block individually (bounded by the packet's own native section size, at most 4096), but as a canonical `BlockState` (block registry key + sorted property map), never a raw native block-state id.

*Registry identity.* Two helpers already established in `PaperSemanticNormalizer` were reused throughout: `registryKey(registry, value)` (via `BuiltInRegistries`, fail-closed on an unregistered value) for static/built-in registries (items, block-entity types, data-component types), and `holderKey(holder)` (via `Holder.unwrapKey()`, fail-closed with `IllegalArgumentException` on an unregistered/direct holder) for dynamic per-world registries (enchantments, damage types). No `ResourceKey`, `Holder`, or other NMS registry type ever crosses into `anticheat-protocol`; every identity is a plain normalized `String`.

*Bounds and DoS safety.* Every new bounded collection follows the codebase's existing pattern of an explicit cap enforced in the record's compact constructor or the normalizer (component count 128, enchantments 32, `otherComponents` 64, container items 256, changed slots 128, entity-data fields 64, passengers/minecart steps already-capped families) — oversized native input throws `IllegalArgumentException`, it does not silently truncate or allocate unbounded memory.

*Unknown-data policy.* Three-way disclosure, consistent with the rest of the codec: known-and-relevant fields get real typed accessors (damage, enchantments, scalar entity-data values); known-but-not-semantically-typed fields get identity-only disclosure (`otherComponents`, `OPAQUE` entity-data kind with an empty value, `HashedStack` empty/non-empty); nothing is claimed the packet does not genuinely carry.

*Native accessor verification.* All 24 entries have native-object tests (no mocks) across four new files — `NativeInventoryTest` (9: item/enchantment/damage/unknown-component round-trips, container content/slot/cursor, equipment, player-inventory-slot, container-data-property, container-button-click/slot-state-changed, container-click), `NativeEntityMiscTest` (6: damage-event with/without optional position, entity-simple-event, look-at, minecart-move, respawn), `NativeWorldMiscTest` (6: chunk-batch/bundle-delimiter markers, explosion, entity-synced-data, block-entity-observation, chunks-biomes, section-blocks-update), and `NativeChunkTest` (2: light-update, chunk-baseline). Two new verification techniques were needed and are documented in-line where used: `VanillaRegistries.createLookup()` + the real public `Holder.Reference.bindComponents(DataComponentMap.EMPTY)` API to legally construct registered `ItemStack`/enchantment/damage-type holders in a test-only bootstrap (extensive `javap`-based research across `Bootstrap`, `BuiltInRegistries`, `MappedRegistry`, `DataComponentInitializers`, and `RegistryLayer` found no caller of `bindComponents` reachable from a minimal `Bootstrap.bootStrap()` harness — reproducing a full dedicated-server startup was judged out of scope, so the real API is called directly instead); and `sun.misc.Unsafe.allocateInstance()` field-injection for `ClientboundLevelChunkPacketData`/`ClientboundLightUpdatePacketData`/`ClientboundLevelChunkWithLightPacket`, whose only public constructors require a real `LevelChunk`/`LevelLightEngine` — the allocated instances are still the real native classes the normalizer reflects into, only constructed without running world-dependent business logic.

**2026-09-16 continuation session (hardening pass against reviewer-identified risks):** an independent Senior Review could not be completed (the reviewer hit its usage limit before finishing) but surfaced three concrete risk areas before stopping: (1) pre-login transport had per-connection bounds but no global admission bound, so many simultaneous connections could still create unbounded aggregate pressure; (2) the periodic pipeline audit might still check the pre-early-hook handler arrangement rather than the current early-hook topology; (3) the PreLoginTransport→identity→PacketEngine.Session binding lifecycle, buffer flush ordering, and shutdown ordering needed edge-case tracing. Full detail in `docs/PHASE_1_HARDENING.md`; summary of what was found and fixed:

- **Global pre-login admission (new):** `PaperCapture` now tracks a global connection count (default cap 4096) and aggregate journal-byte total (default cap 64 MiB, a small fraction of the engine's own 256 MiB budget) across all not-yet-bound connections. A connection beyond the cap gets zero early-hook handlers installed — not blocked, not queued — and still becomes a fully functional session via the pre-existing `attachFresh` fallback once the player joins, only missing pre-login-phase observations (a new `PRELOGIN_ADMISSION_REJECTED` metric makes this explicit). The aggregate byte cap degrades individual connections' journals the same way local overflow already did (new `PRELOGIN_TRUNCATED_GLOBAL` metric). Both counters are released on close or successful bind, guarded against double-release. `bind()` now also surfaces truncation (local or global) into the resulting session's health (`OVERLOADED`) — closing an adjacent, pre-existing gap where truncation was never visible in coverage at all.
- **Pipeline audit — a real, previously undetected bug:** `audit()`'s topology check compared `pipeline.get("encoder")`/`pipeline.get("packet_handler")` against `Audit.encoder`/`Audit.dispatch` fields that are **only ever populated by the `attachFresh` fallback path**, never by `bind()` (the common, early-hook path). This meant the periodic audit (every 20 ticks) would have unconditionally invalidated every early-hook-bound session's health as `PIPELINE_UNCOVERED` the first time it ran — a real player simply staying connected past the first audit tick would have silently lost coverage. Never caught because no test exercised the periodic audit against a real, early-hook-bound session over time. Fixed by re-deriving and recording which of the two real topologies actually attached each session (`Audit.earlyHook`/`inboundAnchor`/`outboundAnchor`) and auditing each against its own correct invariants: adjacency to the recorded anchors always; anchor-handler presence for the early-hook path (no specific encoder/dispatch instance to track, by design — see `docs/PHASE_1_EARLY_TRANSPORT_INVESTIGATION.md` on why `hackfix` was chosen); specific recorded instances for the fallback path (which can legitimately see `encoder` replaced during negotiation).
- **Binding races, buffer flush order, shutdown ordering — traced and proven, not just documented:** old-connection-closes-after-new-connection, bind-while-capture-disabled, duplicate login, and buffer flush ordering across the real gap between a join event and the channel's own event-loop picking up the posted bind task were each proven safe by a passing test against the real `PaperCapture`, following from `PreLoginTransport` being channel-keyed, `SessionKey` being epoch-scoped, and Netty's single-threaded-per-channel event loop guarantee — no code changes were needed for any of these. Shutdown had one real gap: a connection accepted right as `unregisterEarlyHook()` runs could still have its `afterInitChannel` callback in flight on another thread and install permanent state referencing a discarded plugin instance; fixed with a `closing` flag checked before the reflective listener removal completes.
- **Stale control/replay events and resource accounting:** proved (with new tests, no code changes needed) that a `RECORDING`/checkpoint control bridged against a session that is then replaced never applies to the replacement, and audited every release path this pass touches for double-release/underflow. One real, separate bug was found this way: `CaptureWriter` incremented its failure counter *before* invoking the failure callback, a narrow but real test race; fixed by reordering.
- **Broad `catch` review:** zero `catch (Throwable)`/`catch (Exception)` exist anywhere in `anticheat-core`/`anticheat-replay`/`anticheat-packet`/`anticheat-platform-paper` production code — every catch names a specific type, so VM-fatal conditions (`Error`/`ThreadDeath`/`VirtualMachineError`/`LinkageError`) were already never swallowed. Verified, not changed.
- **Package case:** the on-disk source directory for `anticheat-platform-paper` was still lowercase `papea2ac` while every package declaration inside it was uppercase `papea2AC` (not a functional bug — `javac` writes output based on the package statement, not source directory casing — but a latent confusion risk). Renamed the directory to match.

## Packet lifecycle and thread ownership

Installation now happens twice, at two boundaries: an early tap installs at raw connection-accept time via `io.papermc.paper.network.ChannelInitializeListenerHolder`, on the channel's own event loop, before any protocol byte is read (see `docs/PHASE_1_EARLY_TRANSPORT_INVESTIGATION.md`); a later `bind()` call from `PlayerJoinEvent` (Paper main thread) hands the now-identified player session the same, already-installed tap and replays anything captured before that point. The inbound tap precedes `packet_handler`; the outbound tap follows the stable `hackfix` handler rather than `encoder` (which does not exist under that name until protocol negotiation completes). Small native values are copied immediately; native packet objects, `Player`, `ByteBuf`, and other platform handles never enter the core actor. The original traffic is forwarded without a Papea2AC cancellation decision.

Each event loop exclusively increments its connection's capture sequence. Foreign producers submit through a bounded, coalesced MPSC bridge. Sequence is assigned at publication rather than reserved by a producer that can stall. A fixed shard owns each actor, visits at most 32 events/2048 work units, and applies a 2,000,000-unit/s, 200,000-unit-burst session quota. Work exhaustion invalidates certification rather than skipping an input and preserving a contiguous truth claim.

The actor consumes capture order without waiting for missing outcomes. It retains provisional inbound attempts and correlates later outcomes by session/epoch, attempt identity, original digest, processing order, and authoritative revision. Histories and provisional state have one writer. Main-thread read-only service queries read immutable snapshots. The network thread does no file, HTTP, database, or physics work.

## Provisional/certified model

`CAPTURED != CERTIFIED`. Only matching `APPLIED` under a qualified outcome capability, a reconciled baseline, an intact health generation, and a resolved predecessor prefix advances `certifiedIngressOrdinal`. Promotion records the outcome capture sequence separately from the inbound ordinal. The resulting frontier is packet-dispatch truth, not proof of honest movement.

- `REJECTED` invalidates the provisional dependency span; cancellation never advances certification.
- `TRANSFORMED_APPLIED` retains a distinct final server projection only under qualified capability, and leaves the original client frontier uncertified. It cannot resume without reconciliation; no reconciliation provider is claimed here.
- `FAILED`, `UNKNOWN`, mismatched/contradictory outcomes, sequence gaps, lost coverage, and expiry invalidate eligibility. Expiry after 500 ms never implies acceptance.
- Late old-session outcomes cannot mutate a replacement actor. Close is terminal. Cleanup never interprets unresolved work as accepted.
- Outbound write completion is sequenced as a later event, including Netty void promises. Successful handoff does not certify client application. There is no certified ACK/application ledger in this phase implementation.

## Backpressure and observability

Ingress has 1024 slots and a 192 KiB byte bound; the bridge has 256 slots and 64 KiB. Full queues latch health loss before a subsequent certification decision. Closed publication is rejected. The actor journal is limited to 256 entries/256 KiB/500 ms. History is limited to 4096 entries/512 KiB/three seconds with visible eviction count. Large payloads and nested/oversized bundles are rejected by explicit bounds.

Admission reserves 256 MiB global plus 2 MiB per session and leaves 20% of the total budget unused as reserve. Configured session count, shard capacity, and memory floor are independently checked. Replacement retains the old session's charge until cleanup is safe.

Fixed global counters cover processed captures, normalization/provisional promotion, certified/cancelled/mutated/unknown outcomes, expiry, malformed inputs, failures, write failures, queue losses, dispatch rejection, and stalled cleanup. Read-only coverage exposes per-session queue capacity/depth and provisional occupancy. Delay diagnostics include total/samples and conservative power-of-two histogram percentile bounds. Global labels contain no player UUID/name. `CAPTURED` currently counts actor-consumed captures; rejected ingress is counted separately. Event-loop callback timing and complete production monitoring export remain unfinished.

## Failure handling and session lifecycle

Actor ownership is asserted. A runtime exception invalidates the affected session, initiates close, and reports a bounded diagnostic through the platform main-thread logger. Malformed native input invalidates capture coverage while forwarding original traffic to the server's own validation boundary. Asynchronous attach/rejection failures close the session and report failure.

Disconnect/replacement/disable closes admission and schedules an event-loop acknowledgement. The last admitted publisher schedules bounded bridge release; it does not spin waiting on a live publisher. The actor releases ingress only after loop acknowledgement and clears journal/history/projection. Epoch-qualified hook names prevent delayed old-session detach from removing replacement hooks.

Supervisor fencing stops assignment to an unhealthy shard. A proven-terminated writer may have its state reclaimed after transport acknowledgement; a live/hung writer's state stays rooted and charged. Cleanup beyond five seconds produces an alert. A permanently unresponsive external event loop or writer can retain a bounded lease; freeing that memory speculatively would be unsafe. A controlled real shard blocked in replay quota admission is now tested: fencing cannot reclaim its session while its thread remains alive, and termination plus loop acknowledgement permits reclamation. A blocked actual replay writer similarly retains its charges through close. Full shutdown supervision/alert behavior under a genuinely hung native loop remains a qualification gap.

## Replay, configuration, and controls

Transport capsules contain explicit typed event envelopes, bounded semantic payload bytes, relative monotonic times, health barriers, clock events, and close events. The recorder format starts from a coherent empty session and rejects a missing sequence prefix. Per-frame and whole-capsule SHA-256 checks detect corruption; they do not authenticate provenance. Unsupported schemas/profiles, oversized counts/bytes, nested bundles, trailing bytes, and incomplete capsules fail explicitly. There is no Java object deserialization.

Replay imports only replay-schema. Core implements its driver and dispatches DTOs through the protocol-owned mapper to the same truth actor. It recomputes state digests, including pending payloads, deadlines, outcomes, frontiers, capability, and health state. Runtime UUIDs are replaced with a replay pseudonym. Two fresh JVM executions on the current Windows x64 host produce identical outputs. This is transport conformance, not Minecraft physics qualification.

**Live diagnostic prefix recording/export is integrated; the full Phase 1 replay gate is still FAIL.** Production session consumption maps input, clock expiry, health barriers and close through protocol-owned DTO projection. Capture reservation uses the 48 MiB pool and configured-capacity fair shares; promotion and I/O use separate 32/16 MiB pools. A single writer has a two-job queue, at most two 8 MiB I/O leases, four promotion leases globally, and a 64-file diagnostic directory limit. No file I/O runs on packet/main/actor threads. Disconnect exports and releases rolling ownership; explicit `replay <name>` requests are coalesced and serviced by the actor. UUIDs are not written into capture headers or filenames.

A held writer retains promotion/I/O charges until it returns. Failure releases ownership and reports errors. Shutdown closes writer admission only after session cleanup; a live writer remains rooted and charged. Tests exercise actual engine capture-to-file-to-replay, writer failure/hang, quota release and prefix overflow.

This recorder preserves a bounded coherent prefix starting from empty state. Exhaustion stops recording and marks the capsule incomplete. It does not silently evict a required prefix, invent a checkpoint or claim an arbitrary later range is replayable. A health transition racing an actor operation conservatively marks capture incomplete. Adaptive rolling replacement, full coherent mid-session checkpoints, recorded control/resource decisions, writer watchdog alerts and durable closure remain unfinished. This is diagnostic evidence only and does not satisfy NEW-M1.

Startup configuration rejects unknown/duplicate keys, invalid floors and production ENFORCE, and hashes a canonical expanded subset (`schemaVersion`, `mode`, `workers`, `capacity`, `totalBytes`). Operator commands now expose `status`, `player <name>`, `capture on|off`, `effects suspend`, and `replay <name>`, guarded by `papea2ac.admin`. Capture-off closes old epochs and removes hooks; capture-on attaches fresh sessions. Effects remain suspended and there is no production enable command. The synthetic anomaly guard now preserves disabled mode and freezes the eligible population for a window. Tests and a local Paper console smoke verify these controls. Full ordered configuration/control application records, runtime budget changes/replay and the full guard/action-outcome bridge remain incomplete: runtime-controls acceptance remains FAIL rather than treating an isolated synthetic guard as production enforcement.
